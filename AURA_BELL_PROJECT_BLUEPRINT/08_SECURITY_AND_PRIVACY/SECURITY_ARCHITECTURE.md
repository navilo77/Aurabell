# Aura Bell — Security Architecture (সিকিউরিটি আর্কিটেকচার)

## ১. সিকিউরিটি ওভারভিউ
Aura Bell প্ল্যাটফর্মটি **Defense-in-Depth** নীতিমালার ওপর প্রতিষ্ঠিত। 

```text
ক্লায়েন্ট রিকোয়েস্ট (HTTPS / TLS 1.3)
      ⬇️
WAF / CDN (DDoS Mitigation & Rate Limiting)
      ⬇️
FastAPI Security Middleware (CORS, JWT Signature, RBAC)
      ⬇️
SQLAlchemy Parameterized Queries (No SQL Injection)
      ⬇️
PostgreSQL Row Level Security (RLS) & DB Constraints
```

---

## ২. মূল নিরাপত্তা স্তম্ভ
* **জিরো ট্রাস্ট ক্লায়েন্ট ইনপুট**: ক্লায়েন্ট থেকে আসা কোনো ডেটা সরাসরি কার্যকর করা যাবে না। Pydantic স্কিমা দিয়ে টাইপ ও রেঞ্জ ভ্যালিডেশন বাধ্যতামূলক।
* **ক্রিপ্টোগ্রাফিক ওয়েবহুক ভ্যালিডেশন**: গেটওয়ে প্রেরিত সিক্রেট টোকেন ও এইচএমএসি সিগনেচার যাচাই ব্যতীত পেমেন্ট আপডেট গ্রহণ করা সম্পূর্ণ নিষিদ্ধ।
* **সিক্রেট কি বিচ্ছিন্নকরণ**: Supabase `service_role` সিক্রেট কি কখনোই ফ্রন্টএন্ডে বা ক্লায়েন্ট বান্ডেলে যুক্ত করা যাবে না; এটি কেবল সুরক্ষিত ব্যাকএন্ড এনভায়রনমেন্ট ভ্যারিয়েবলে থাকবে।

## ৩. হাইব্রিড লোকাল-ফাস্ট — ক্লায়েন্ট সাইড নিরাপত্তা সীমা (টার্গেট আর্কিটেকচার)

হাইব্রিড লোকাল-ফাস্ট আর্কিটেকচারে ক্লায়েন্ট-সাইড পারসিস্টেন্সের নিরাপত্তা সীমা নিচের অনুযায়ী বসবে:

* **IndexedDB অ-trusted ক্লায়েন্ট স্টোরেজ**: IndexedDB/লোকাল স্টেট কখনো bijনেস-ক্রিটিক্যাল ডাটাবেজের প্রতিস্থাপন নয় এবং কখনোই বিশ্বাসযোগ্য নয়। ক্লায়েন্ট-সাইড স্টেট কখনোই সার্ভার অথরাইজেশন বা বিজনেস ভ্যালিডেশন বাইপাস করবে না।
* **লোকাল ক্যাশ ইন্টিগ্রিটি**: লোকাল ক্যাশে সংরক্ষিত ডেটা রেসপন্সিভনেস ও অফলাইন continuity-এর জন্য ব্যবহার করা যেতে পারে, কিন্তু bijনেস-ক্রিটিক্যাল অপারেশন চূড়ান্ত করার আগে সার্ভার ভ্যালিডেশন অপরিহার্য।
* **সংবেদনশীল ডেটা সীমাবদ্ধতা**: পেমেন্ট ডেটা, অর্ডার স্টেট, মূল্য, ইনভেন্টরিarder bijনেস-ক্রিটিক্যাল ডেটা কেবল সার্ভে>Authoritatively সংরক্ষণ হবে। ক্লায়েন্টে শুধুমাত্র ক্যাশড কপি থাকতে পারে, অথরিটেটিভ রেকর্ড নয়।
* **সার্ভারে অথরাইজেশন এনফোর্সমেন্ট**: সমস্ত bijনেস-ক্রিটিক্যাল অপারেশনের অথরাইজেশন সার্ভার সাইডে এনফোর্স করা হবে। ক্লায়েন্ট-সাইড স্টেট অথরাইজেশন বাইপাস করতে পারবে না।
* **রিপ্লে/আইডেমপোটেন্সি**: অফলাইন মিউটেশন সিঙ্কের সময় রিপ্লে অ্যাটাক প্রতিরোধ ও আইডেমপোটেন্সি নিশ্চিত করা হবে। (অ্যাক্সেক্ট মেকানিজম ইমপ্লিমেন্টেশন ফেজে সিদ্ধান্ত নেওয়া হবে।)
* **মালিশাস ক্লায়েন্ট মডিফিকেশন**: ক্লায়েন্ট-সাইড স্টেটে অবাঞ্ছিত পরিবর্তনের সম্ভাবনা বিবেচনা করে, সার্ভার সাইডে সমস্ত ইনপুট ভ্যালিডেশন বাধ্যতামূলক।
* **অফলাইন মিউটেশন ট্যাম্পারিং**: অফলাইনে মিউটেশন কিউে ট্যাম্পারিং রোধ করতে সার্ভার সাইডে মিউটেশন আইডেন্টিফায়ার ও সিকোয়েন্স ভ্যালিডেশন প্রয়োজন হবে। (অ্যাক্সেক্ট ইমপ্লিমেন্টেশন ইমপ্লিমেন্টেশন ফেজে সিদ্ধান্ত নেওয়া হবে।)

বর্তমান Defense-in-Depth লেয়ার (WAF/CDN → FastAPI Security Middleware → SQLAlchemy Parameterized Queries → PostgreSQL RLS) বজায় থাকবে।
