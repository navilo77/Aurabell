# Aura Bell — Frontend Architecture (ফ্রন্টএন্ড আর্কিটেকচার)

## ১. ফ্রন্টএন্ড ওভারভিউ
Next.js 14+ (App Router) ব্যবহার করে প্ল্যাটফর্মের গ্রাহক ও এডমিন ইন্টারফেস নির্মিত হবে।

### প্রস্তাবিত ডিরেক্টরি কাঠামো:
```text
frontend/
├── app/
│   ├── (storefront)/             # কাস্টমার ফেসিং স্টোরফ্রন্ট
│   │   ├── best-gadget/          # Best Gadget স্টোরের পেজসমূহ
│   │   ├── aura-skin-care/       # Aura Skin Care স্টোরের পেজসমূহ
│   │   ├── cart/                 # শেয়ার্ড কার্ট পেজ
│   │   ├── checkout/             # ইউনিফাইড চেকআউট পেজ
│   │   └── account/              # কাস্টমার প্রোফাইল ও অর্ডার হিস্ট্রি
│   ├── (admin)/                  # এডমিন ব্যাকঅফিস পোর্টাল
│   │   ├── dashboard/
│   │   ├── orders/
│   │   ├── inventory/
│   │   └── reports/
│   └── api/                      # নেক্সট.জেএস বিএফএফ (BFF / Proxy) রাউটস
├── components/                   # রিইউজেবল ইউআই কম্পোনেন্টস
├── lib/                          # এপিআই ক্লায়েন্ট, ফরম্যাটার ও ইউটিলিটি
└── styles/                       # Tailwind CSS গ্লোবাল স্টাইলিং
```

## ২. স্টেট ম্যানেজমেন্ট ও ডেটা ফেচিং

### হাইব্রিড লোকাল-ফাস্ট লেয়ার (টার্গেট আর্কিটেকচার)
ক্লায়েন্ট-সাইড ডেটা ফ্লো নিচের লেয়ার অনুযায়ী বসবে:

```text
UI / Components
      ↓
Client State (Zustand/Context)
      ↓
Local Cache / IndexedDB
      ↓
Sync / Mutation Queue
      ↓
API Layer
      ↓
FastAPI
```

### Client State
জুস্ত্যান্ড/কন্টেক্সট ভিত্তিক ক্লায়েন্ট স্টেট আর্কিটেকচার বজায় থাকবে। শপিং কার্ট এবং ক্লায়েন্ট সেশন স্টেট ম্যানেজ করা হবে।

### Local Persistence (Target)
IndexedDB ক্লায়েন্ট-সাইড লোকাল ক্যাশ/পারসিস্টেন্স লেয়ার হিসেবে ব্যবহার হবে। ক্যাশড ক্যাটালগ, প্রোডাক্ট ডিটেইলস, কার্ট ড্রাফট, wishlist/recently viewed এবং পেন্ডিং মিউটেশন কিউ এখানে রাখা যেতে পারে।

### Offline-Capable Data
ক্যাশড ক্যাটালগ ব্রাউজিং, ক্যাশড প্রোডাক্ট ডিটেইলস, কার্ট ড্রাফট, wishlist/recently viewed পোল-এ নিরাপদ লোকাল অপারেশন অফলাইন-সক্ষম হতে পারে।

### Optimistic UI
কার্টে আইটেম বাড়ানো বা কমানোর মতো নিরাপদ ইউজার ইন্টারঅ্যাকশনের ক্ষেত্রে অপটিমিস্টিক আপডেট থাকবে।

### Mutation Queue (Target)
অফলাইন-সক্ষম মিউটেশন পেন্ডিং স্টেট হিসেবে কিউ করা যাবে এবং অনলাইন হলে সার্ভারের সাথে সিঙ্ক হবে। রিট্রাই/রিকনসিলিয়েশন কনসেপচুয়ালি ডকুমেন্ট করা হবে, কিন্তু এক্সাক্ট অ্যালগরিদম ফাইনালাইজ করা হবে না।

### Server-Required Operations (Authoritative)
নিচের bijনেস-ক্রিটিক্যাল অপারেশনের চূড়ান্ত প্রাধিকার সার্ভারে থাকে:
- চূড়ান্ত চেকআউট
- পেমেন্ট
- চূড়ান্ত মূল্য ভ্যালিডেশন
- চূড়ান্ত স্টক ভ্যালিডেশন
- চূড়ান্ত অর্ডার কনফার্মেশন
- অথরিটেটিভ অর্ডার স্টেট

### Current Implementation vs Target
বর্তমান ইমপ্লিমেন্টেশনে IndexedDB ক্লায়েন্ট-সাইড লোকাল ক্যাশ/পারসিস্টেন্স লেয়ার ইমপ্লিমেন্ট করা হয়েছে, মিউটেশন কিউ (`drainPromise` লক, অ্যাকাউন্ট-স্কোপড মিউটেশন, idempotency কী হেডার, ব্যাকঅফ+জিটার, ডেড-লেটার) এবং অফলাইন সিঙ্ক ইমপ্লিমেন্ট করা হয়েছে। লোকালস্টোরেজ-বেসড টোকেন স্টোরেজ বাদ দিয়ে HTTPOnly কুকি (`aura_access_token`, `aura_refresh_token`) ব্যবহার করা হচ্ছে।

হাইব্রিড লোকাল-ফাস্ট টার্গেট আর্কিটেকচার ইমপ্লিমেন্টেশন গ্যাপ সমাধান করা হয়েছে।

Server Components এসইও এবং দ্রুত ফার্স্ট কন্টেন্টফুল পেইন্ট (FCP) এর জন্য প্রোডাক্ট লিস্টিং ও ক্যাটাগরি পেজ সার্ভারে রেন্ডার হবে।
