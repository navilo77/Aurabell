# Kilo Code Instructions (কিলো কোড সিস্টেম নির্দেশনা)

Kilo Code বা যে কোনো এআই কোডিং এজেন্টের জন্য বাধ্যতামূলক অপারেশনাল নির্দেশনা:

## ১. প্রি-এক্সিকিউশন প্রোটোকল (Pre-Execution Protocol)
* যে কোনো ফাইল পরিবর্তনের আগে সংশ্লিষ্ট ফাইলটি সম্পূর্ণরূপে রিড করুন।
* কখনো আন্দাজে ফাইল পাথ বা এপিআই প্যারামিটার অনুমান করবেন না।
* `AURA_BELL_PROJECT_BLUEPRINT/` ফোল্ডারের বাইরে কোনো প্রজেক্ট ডকুমেন্টেশন তৈরি করবেন না।
* **স্থায়ী ফাইল বিন্যাস নীতি (DOC-AUR-172)**: রুট ডিরেক্টরিতে কোনো ফাইল তৈরি সম্পূর্ণ নিষিদ্ধ। যে কোনো ফাইল তৈরির পূর্বে অবশ্যই `PERMANENT_FILE_ORGANIZATION_RULES.md` মেনে নির্দিষ্ট ক্যাটাগরি ফোল্ডার নির্বাচন করুন এবং `DOCUMENT_INDEX.md` আপডেট করুন।

## ২. কোডিং ও বাস্তবায়ন নীতি (Execution Discipline)
* সর্বদা টাইপ-অ্যানোটেড পাইথন ৩.১১+ এবং টাইপস্ক্রিপ্ট ব্যবহার করুন (`strict: true`)।
* ডাটাবেজে নতুন কলাম বা টেবিল যোগ করার প্রয়োজন হলে প্রথমে `05_DATABASE/DATABASE_SCHEMA.md` আপডেট করতে হবে এবং ওনারের অনুমোদন সাপেক্ষে মাইগ্রেশন লিখতে হবে।
* স্টকের কোনো পরিবর্তন লিখতে গেলে অবশ্যই নিশ্চিত করুন যে `stock_movements` টেবিলে সংশ্লিষ্ট রেকর্ড সংরক্ষিত হচ্ছে।

## ৩. পরম বিধিনিষেধ (Strict Prohibitions)
* কোনো অবস্থাতেই ফ্রন্টএন্ড থেকে আসা `price` বা `total_amount` ফিল্ডকে সত্য বলে বিশ্বাস করবেন না।
* কোনো অবস্থাতেই Supabase `service_role` কি ফ্রন্টএন্ড কোডে আমদানি করবেন না।
* কোনো অবস্থাতেই অনুমোদন ছাড়া রেডিস, কাফকা বা মাইক্রোসার্ভিস ফ্রেমওয়ার্ক চালু করবেন না।

## ৪. মাইলস্টোন চেকলিস্ট আপডেট প্রোটোকল (Milestone TODO Update Protocol)
* **বাধ্যতামূলক চেকলিস্ট আপডেট**: যে কোনো সাব-মাইলস্টোন (যেমন: M1.1, M1.2 ইত্যাদি) বা প্রধান মাইলস্টোনের কাজ ও ভেরিফিকেশন সফলভাবে শেষ হওয়ার সাথে সাথে সংশ্লিষ্ট এজেন্টকে অবশ্যই রুট ডিরেক্টরির `MILESTONES.md` ফাইলে গিয়ে চেকবক্সটিকে `- [ ]` থেকে `- [x]` মার্ক করতে হবে।
* **মেটাডাটা এন্ট্রি**: সাব-মাইলস্টোনের স্ট্যাটাস `COMPLETED`, সমাপ্তির তারিখ ও এজেন্টের নাম রেকর্ড করতে হবে।
* **অগ্রগতি রিকনসিলিয়েশন**: মূল মাইলস্টোনের সমস্ত সাব-মাইলস্টোন শেষ হলে মূল মাইলস্টোনকে `COMPLETED` করে অগ্রগতি ম্যাট্রিক্স আপডেট করতে হবে।

## ৫. সহজ বাংলা যোগাযোগ নীতি (Bangla Communication Standard)
* সমস্ত ব্যাখ্যা, অগ্রগতি আপডেট ও প্রশ্নের উত্তর **সহজ, সাবলীল ও স্পষ্ট বাংলায়** প্রদান করতে হবে।
* জটিল বা দুর্বোধ্য রোবোটিক ভাষা পরিহার করে একজন অভিজ্ঞ সহকর্মী ইঞ্জিনিয়ারের মতো প্রাঞ্জল ভাষায় কথা বলতে হবে (প্রয়োজনীয় ইংরেজি টেকনিক্যাল টার্মস যেমন: JWT, ORM, Webhook অক্ষুণ্ণ রেখে)।

## ৬. বাংলায় কোড কমেন্টিং স্ট্যান্ডার্ড (Mandatory Bangla Code Comments)
কোডবেসের প্রতিটি গুরুত্বপূর্ণ ফাংশন, ক্লাস, এপিআই রাউট বা সার্ভিস লজিকের শীর্ষে **বাধ্যতামূলকভাবে সহজ বাংলায় ৩টি নির্দিষ্ট প্রশ্নের উত্তর কমেন্ট আকারে লিখতে হবে**:

1. **উদ্দেশ্য (Why)**: এই কোড বা ফাংশনটি কেন লেখা হয়েছে? এটি কী কাজ সম্পন্ন করে?
2. **সংযুক্ত ফাইল (Connected Files)**: এটি কোন মডেল, ডাটাবেজ টেবিল, স্কিমা বা সার্ভিসের সাথে সম্পর্কিত?
3. **ওয়ার্কফ্লো (Workflow Path)**: রিকোয়েস্ট বা ডেটা কোথা থেকে আসছে, কোথায় ভ্যালিডেট হচ্ছে এবং ফলাফল কোথায় গিয়ে শেষ হচ্ছে?

## ৭. কোয়ালিটি গেট ও গিট কমিট/পুশ প্রোটোকল (Audit ➔ Test ➔ Verify ➔ Commit ➔ Push)

যেকোনো প্রধান মাইলস্টোন (M1 থেকে M6) বা সাব-মাইলস্টোন শেষ করার পর **গিট কমিট ও পুশ করার আগে নিচের ৫টি ধাপ বাধ্যতামূলকভাবে সম্পন্ন করতে হবে**:

### ধাপ ১: প্রি-কমিট অডিট (Pre-Commit Audit)
* রুট ডিরেক্টরি পরিচ্ছন্ন কি না পরীক্ষা করুন (কোনো `.env`, লগ বা সাময়িক ফাইল যেন গিটে স্টেজ না হয়)।
* কোডে কোনো পাসওয়ার্ড বা সিক্রেট কি হার্ডকোড করা নেই তা নিশ্চিত করুন।

### ধাপ ২: রিয়েল টেস্টিং (Real Automated Testing)
* সংশ্লিষ্ট ফিচারের ইউনিট টেস্ট ও ইন্টিগ্রেশন টেস্ট রান করতে হবে (`pytest` বা টেস্ট স্ক্রিপ্ট)।
* **কঠোর নিয়ম**: কোনো টেস্ট ব্যর্থ (Failed) হলে কোনো অবস্থাতেই কোড কমিট বা পুশ করা যাবে না। টেস্ট ফিক্স করে ১০০% পাস করাতে হবে।

### ধাপ ৩: ভেরিফিকেশন ও চেকলিস্ট আপডেট (Checklist Update)
* রুট ডিরেক্টরির `MILESTONES.md` ফাইলে সংশ্লিষ্ট মাইলস্টোনের বক্সে `- [x]` মার্ক করতে হবে এবং সমাপ্তির তারিখ রেকর্ড করতে হবে।

### ধাপ ৪: বিস্তারিত বর্ণনামূলক গিট কমিট ও ট্যাগ (Descriptive Git Commit & Tag)
প্রতিটি মাইলস্টোনের কমিট মেসেজ হতে হবে সুস্পষ্ট, বিস্তারিত এবং বহু-লাইনভিত্তিক বিবরণ সংবলিত:
```bash
git add .

- Scaffolded modular monolith FastAPI backend with Pydantic v2 settings.
- Successfully executed Supabase PostgreSQL 43 tables DDL migration and triggers.
- Integrated Supabase GoTrue Auth with JWT verification and RBAC middleware.
- Seeded default warehouse, system roles, and stores (Best Gadget & Aura Skin Care).
- Test Results: 14/14 automated tests passed (100%).
- Updated MILESTONES.md checklist to COMPLETED."
```

### ধাপ ৫: গিট পুশ (Push to Remote)
* টেস্ট ও অডিটে শতভাগ উত্তীর্ণ হওয়ার পর দূরবর্তী রিপোজিটরিতে ট্যাগসহ পুশ সম্পন্ন করতে হবে:
```bash
git push origin main --tags
```
