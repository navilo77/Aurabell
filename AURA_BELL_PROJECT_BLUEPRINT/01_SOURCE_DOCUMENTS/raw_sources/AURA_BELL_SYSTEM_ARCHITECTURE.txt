১. সিস্টেম আর্কিটেকচার পরিচিতি
Aura Bell একটি Multi-Store E-commerce Platform। এর জন্য এমন একটি প্রযুক্তিগত কাঠামো তৈরি করা হবে, যেখানে একাধিক স্টোর, গ্রাহক, পণ্য, ইনভেন্টরি, অর্ডার, পেমেন্ট ও ডেলিভারি একটি কেন্দ্রীয় সিস্টেমের অধীনে কাজ করবে।
প্রাথমিক Architecture হবে Modular Monolith।
এর অর্থ:
* একটি কেন্দ্রীয় Backend Application থাকবে।
* একটি কেন্দ্রীয় PostgreSQL Database থাকবে।
* প্রতিটি Business Module-এর নিজস্ব দায়িত্ব থাকবে।
* Module-গুলোর মধ্যে নির্ধারিত নিয়মে যোগাযোগ হবে।
* ভবিষ্যতে প্রয়োজন হলে নির্দিষ্ট Module আলাদা Service করা যাবে।
প্রথম থেকেই Microservices তৈরি করা হবে না।

৬. Checkout Processing Architecture
Checkout হলো Aura Bell-এর সবচেয়ে গুরুত্বপূর্ণ Business Workflow-গুলোর একটি।
CUSTOMER CART
     |
     v
BACKEND VALIDATION
     |
     v
RECALCULATE PRICE
     |
     v
CHECK INVENTORY
     |
     v
RESERVE STOCK
     |
     v
CREATE PARENT ORDER
     |
     v
CREATE STORE ORDERS
     |
     v
SAVE ORDER SNAPSHOTS
     |
     v
DATABASE TRANSACTION COMMIT
     |
     v
PAYMENT / COD WORKFLOW


গুরুত্বপূর্ণ নিয়ম
* Price Backend থেকে পুনরায় হিসাব করতে হবে।
* Stock Reservation Atomic ও Concurrency-safe হতে হবে।
* Database Transaction ব্যর্থ হলে আংশিক Order তৈরি হওয়া যাবে না।
* একই Checkout Request পুনরায় এলে Idempotency ব্যবস্থা থাকতে হবে।
* Payment ব্যর্থ হলে নির্ধারিত নিয়ম অনুযায়ী Order ও Stock Reservation পরিচালিত হবে।

৮. Payment Architecture
Payment Integration Adapter Pattern ব্যবহার করবে।
FASTAPI PAYMENT MODULE
          |
          v
   PAYMENT ADAPTER
          |
     +----+----+
     |         |
     v         v
 Provider A  Provider B


প্রাথমিক পর্যায়ে একটি Gateway যথেষ্ট।
Webhook Processing
1. Provider থেকে Webhook আসবে।
2. Signature যাচাই হবে।
3. Provider Event ID পরীক্ষা হবে।
4. Duplicate Event হলে পুনরায় Business Action হবে না।
5. Payment Transaction সংরক্ষণ হবে।
6. সংশ্লিষ্ট Payment Status Update হবে।
7. প্রয়োজন হলে Order Workflow Update হবে।
Webhook Event ID-তে Unique Constraint থাকতে হবে।
৯. Background Worker Architecture
প্রথমে PostgreSQL-backed Outbox Pattern ব্যবহার করা হবে।
BUSINESS TRANSACTION
        |
        v
   OUTBOX EVENT
        |
        v
 BACKGROUND WORKER
        |
   +----+------+---------+
   |           |         |
   v           v         v
 Email       SMS     Notifications


Worker-এর কাজ:
* Notification।
* Email।
* SMS।
* Retry Failed Jobs।
* Order Event Processing।
* Scheduled Stock Reservation Release।
শুরুতে Kafka বা RabbitMQ প্রয়োজন নেই।
১০. Authentication ও Authorization
Supabase Auth User Authentication পরিচালনা করবে।
FastAPI প্রতিটি Protected Request-এর JWT যাচাই করবে।
যাচাইয়ের বিষয়:
* Token Signature।
* Issuer।
* Audience।
* Expiry।
Authorization-এর জন্য Role-Based Access Control (RBAC) ব্যবহার করা হবে।
প্রাথমিক Role:
* Owner।
* Admin।
* Store Manager।
* Inventory Manager।
* Order Manager।
* Support Agent।
* Customer।
Store-level Permission থাকতে হবে।
Database Row Level Security (RLS) অতিরিক্ত সুরক্ষা হিসেবে থাকবে।
Supabase Service Role Key কখনো Frontend-এ প্রকাশ করা যাবে না।

* Module-গুলোর মধ্যে নির্ধারিত নিয়মে যোগাযোগ হবে।
