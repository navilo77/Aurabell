# M1.3 — Auth Security Layers

## Overview

Aura Bell implements defense-in-depth authentication and authorization across four layers:

```
┌─────────────────────────────────────────────────────────────────┐
│ 1. TRANSPORT LAYER (HTTPS/TLS)                                 │
│    └─ HSTS, Secure Cookies, TrustedHost, CORS                  │
├─────────────────────────────────────────────────────────────────┤
│ 2. JWT TOKEN LAYER                                             │
│    └─ RS256 via Supabase GoTrue JWKS, iss/aud/exp validation   │
├─────────────────────────────────────────────────────────────────┤
│ 3. RBAC LAYER (require_role)                                   │
│    └─ Role-based access control at API gateway level           │
├─────────────────────────────────────────────────────────────────┤
│ 4. RLS LAYER (Row Level Security)                              │
│    └─ Database-enforced policies per table                     │
└─────────────────────────────────────────────────────────────────┘
```

## Layer 1: Transport Hardening

- **HSTS**: `Strict-Transport-Security: max-age=31536000; includeSubDomains; preload`
- **Secure Cookies**: `Secure`, `HttpOnly`, `SameSite=Lax`
- **TrustedHost**: Validates `Host` header against allowed hosts
- **CORS**: Restricts origins to configured frontend URLs

## Layer 2: JWT Validation (Supabase GoTrue)

- **Algorithm**: RS256 (asymmetric, public key verification)
- **JWKS Source**: `SUPABASE_URL + "/auth/v1/.well-known/jwks.json"` (cached 1 hour)
- **Claims Validated**:
  - `iss` = `SUPABASE_URL + "/auth/v1"`
  - `aud` = `"authenticated"`
  - `exp` = not in past
  - `signature` = verified against JWKS

## Layer 3: RBAC (`require_role`)

```python
# Usage in routes
@router.get("/admin")
async def admin_only(user: User = Depends(require_role("admin", "owner"))):
    ...

# Role hierarchy (from seed):
# owner > admin > store_manager > inventory_manager > order_manager > support_agent > customer
```

- Checks user roles loaded from `user_roles` + `roles` tables
- Caches `User` object in `request.state.user` per request
- Returns 403 if user lacks ALL required roles

## Layer 4: RLS (Row Level Security)

PostgreSQL policies enforce data isolation at database level:

```sql
-- Example: profiles table
CREATE POLICY "Users can read own profile"
ON public.profiles FOR SELECT TO authenticated
USING (id = auth.uid());
```

- Policies use `auth.uid()` from JWT `sub` claim
- Store-scoped roles use `user_roles.store_id` for multi-tenancy
- Warehouse access restricted to `store_manager` of that store


## Error Handling

All auth failures raise `AuthError` subclasses:
- `InvalidTokenError` (401) - malformed or bad signature
- `ExpiredTokenError` (401) - `exp` claim passed
- `InvalidIssuerError` (401) - wrong `iss`
- `InvalidAudienceError` (401) - wrong `aud`
- `JWKSFetchError` (503) - JWKS unavailable
- `UserNotFoundError` (401) - no profile for `sub`
- `PermissionDenied` (403) - insufficient roles
