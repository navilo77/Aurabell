# M1.4 — Main Central Warehouse Design

## Decision Summary

**Decision D2**: Link central warehouse to **Best Gadget** (slug: `best-gadget`)

**Rationale**:
- Best Gadget is the first store inserted in migration 010
- Primary revenue store (electronics/gadgets)
- Simpler than creating a "Platform Anchor" store
- No clear advantage to Aura Skin Care

## RLS Policy Design

```sql
-- Migration 011: Warehouse RLS + Seed

ALTER TABLE public.warehouses ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Store managers manage own warehouses"
ON public.warehouses FOR ALL TO authenticated
USING (
    store_id IN (
        SELECT store_id FROM public.user_roles
        WHERE user_id = auth.uid()
        AND role_id = (SELECT id FROM public.roles WHERE name = 'store_manager')
        AND store_id IS NOT NULL
    )
)
WITH CHECK (
    store_id IN (
        SELECT store_id FROM public.user_roles
        WHERE user_id = auth.uid()
        AND role_id = (SELECT id FROM public.roles WHERE name = 'store_manager')
        AND store_id IS NOT NULL
    )
);
```

### Policy Analysis

| Aspect | Implementation |
|--------|---------------|
| **Table** | `public.warehouses` |
| **Operation** | `FOR ALL` (SELECT, INSERT, UPDATE, DELETE) |
| **Role** | `authenticated` (any logged-in user) |
| **USING clause** | Filters visible rows |
| **WITH CHECK clause** | Filters writable rows |
| **Role filter** | `role_id = store_manager` |
| **Store scope** | `store_id IS NOT NULL` guard |
| **Subquery** | `user_roles` → user's store_manager assignments |

### Why This Pattern?

1. **Mirrors existing policies** (migration 009): Uses `EXISTS` subquery with `auth.uid()`
2. **Store-scoped**: Only `store_manager` with `store_id` can access
3. **Global roles excluded**: `AND store_id IS NOT NULL` prevents global store_managers
4. **Symmetric USING/WITH CHECK**: Same logic for read and write

## Access Matrix

| Role | Warehouse Access |
|------|-----------------|
| `owner` | None via RLS (uses service role for admin) |
| `admin` | None via RLS (uses service role for admin) |
| `store_manager` | **Own store's warehouse(s) only** |
| `inventory_manager` | None (separate inventory permissions) |
| `order_manager` | None |
| `support_agent` | None |
| `customer` | None |

**Note**: Platform roles (`owner`, `admin`) use service role key for admin operations, bypassing RLS entirely.
