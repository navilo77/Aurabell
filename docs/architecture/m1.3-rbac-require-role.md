# M1.3 — RBAC: require_role Factory

## Overview

`require_role(*roles)` is a FastAPI dependency factory that enforces role-based access control at the API gateway layer.

## Usage

```python
from app.core.auth import require_role

# Single role
@router.get("/manager")
async def manager_only(user: User = Depends(require_role("store_manager"))):
    ...

# Multiple roles (OR logic - user needs ANY)
@router.get("/admin")
async def admin_or_owner(user: User = Depends(require_role("admin", "owner"))):
    ...

# In route with other dependencies
@router.post("/orders")
async def create_order(
    data: OrderCreate,
    user: User = Depends(require_role("order_manager", "store_manager")),
    db: AsyncSession = Depends(get_db),
):
    ...
```

## Implementation

```python
# app/core/auth.py

def require_role(*required_roles: str) -> Callable[[], Awaitable[User]]:
    if not required_roles:
        raise ValueError("require_role requires at least one role")

    async def role_checker(user: User = Depends(get_current_user)) -> User:
        user_roles = set(user.roles)
        required = set(required_roles)

        if not user_roles & required:
            raise HTTPException(
                status_code=403,
                detail=PermissionDenied(
                    required_roles=list(required_roles),
                    user_roles=user.roles,
                ).message,
            )
        return user

    return role_checker
```

## Role Hierarchy (from migration 010)

| Role | Level | Description |
|------|-------|-------------|
| `owner` | 7 | Platform owner - full access |
| `admin` | 6 | Platform administrator |
| `store_manager` | 5 | Store management (store-scoped) |
| `inventory_manager` | 4 | Inventory management |
| `order_manager` | 3 | Order management |
| `support_agent` | 2 | Customer support |
| `customer` | 1 | Customer account |

**Note**: `require_role` uses OR logic (any match passes), not hierarchy. For hierarchy, check `user.roles` directly.

## User Role Loading

Roles are loaded in `get_current_user()`:

```sql
SELECT p.id, p.email, r.name as role_name
FROM public.profiles p
JOIN public.user_roles ur ON ur.user_id = p.id
JOIN public.roles r ON r.id = ur.role_id
WHERE p.id = :user_id
```

- Returns all roles assigned to user (can have multiple)
- Roles can be global (`user_roles.store_id IS NULL`) or store-scoped
- Cached in `request.state.user` for subsequent calls

## Caching

```python
# In get_current_user()
if hasattr(request.state, "user") and request.state.user is not None:
    return request.state.user  # Skip JWT verify + DB query
```

- Per-request cache in `request.state.user`
- Invalidated automatically per request
- No cross-request caching (security)

## Error Responses

| Scenario | Status | Response Body |
|----------|--------|---------------|
| Missing auth header | 401 | `{"detail": "Missing authorization header", "code": "AUTH_ERROR"}` |
| Invalid/expired token | 401 | `{"detail": "Token has expired", "code": "TOKEN_EXPIRED"}` |
| User not in DB | 401 | `{"detail": "User not found", "code": "USER_NOT_FOUND"}` |
| Missing required role | 403 | `{"detail": "Insufficient permissions", "code": "PERMISSION_DENIED"}` |

## Testing

```python
# Test allow
user = User(id="1", email="a@b.com", roles=["store_manager"])
checker = require_role("store_manager", "admin")
await checker(user=user)  # Passes

# Test deny
user = User(id="2", email="c@d.com", roles=["customer"])
checker = require_role("store_manager")
await checker(user=user)  # Raises HTTPException 403
```

## Integration with RLS

`require_role` operates at **API gateway layer** (Layer 3). RLS (Layer 4) provides defense-in-depth:

- API layer: Fast fail, clear error messages, no DB round-trip for unauthorized
- DB layer: Enforces policies even if API bypassed, protects direct DB access
- Both use same role data from `user_roles` + `roles` tables
