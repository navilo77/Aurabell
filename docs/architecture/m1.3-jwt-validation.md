# M1.3 — JWT Validation Implementation

## JWKS Fetch & Caching

```python
# app/core/security.py

_jwks_cache: dict | None = None
_jwks_fetched_at: float = 0.0
_JWKS_TTL_SECONDS = 3600  # 1 hour

async def get_jwks() -> dict:
    """Get JWKS, using cache if valid (1 hour TTL)."""
    global _jwks_cache, _jwks_fetched_at

    now = time.time()
    if _jwks_cache and (now - _jwks_fetched_at) < _JWKS_TTL_SECONDS:
        return _jwks_cache

    _jwks_cache = await _fetch_jwks()
    _jwks_fetched_at = now
    return _jwks_cache
```

- **Endpoint**: `{SUPABASE_URL}/auth/v1/.well-known/jwks.json`
- **Cache TTL**: 1 hour (3600 seconds)
- **Fail-closed**: On fetch failure → raise `JWKSFetchError` (503), never fall back to service role

## verify_token() Logic

```python
async def verify_token(token: str) -> dict:
    """Verify JWT token from Supabase GoTrue."""
    jwks = await get_jwks()
    expected_issuer = _get_expected_issuer()  # SUPABASE_URL + "/auth/v1"

    payload = jwt.decode(
        token,
        jwks,
        algorithms=["RS256"],
        audience="authenticated",
        issuer=expected_issuer,
        options={
            "verify_signature": True,
            "verify_aud": True,
            "verify_iss": True,
            "verify_exp": True,
        },
    )
    return payload
```

## Claim Validation Details

| Claim | Expected Value | Validation | Error on Failure |
|-------|---------------|------------|------------------|
| `alg` | RS256 | Header must match | `InvalidTokenError` |
| `kid` | Must exist in JWKS | Key lookup | `InvalidTokenError` |
| `signature` | Valid RSA-PKCS1v15 | Cryptographic verify | `InvalidTokenError` |
| `iss` | `{SUPABASE_URL}/auth/v1` | String equality | `InvalidIssuerError` |
| `aud` | `"authenticated"` | String equality | `InvalidAudienceError` |
| `exp` | > now (Unix timestamp) | Time comparison | `ExpiredTokenError` |
| `sub` | Non-empty string | Presence check | `InvalidTokenError` (in auth.py) |

## Error Mapping

| jose Exception | Mapped To | HTTP Status |
|---------------|-----------|-------------|
| `ExpiredSignatureError` | `ExpiredTokenError` | 401 |
| `JWTClaimsError` (aud) | `InvalidAudienceError` | 401 |
| `JWTClaimsError` (iss) | `InvalidIssuerError` | 401 |
| `JWSError` / `JWKError` | `InvalidTokenError` | 401 |
| `httpx.HTTPError` | `JWKSFetchError` | 503 |

## Security Considerations

1. **No service role for verification**: `SUPABASE_SERVICE_ROLE_KEY` bypasses RLS — never use for token validation
2. **Cache poisoning protection**: JWKS cached in memory only, TTL enforced
3. **Clock skew**: No leeway configured; rely on Supabase token issuance time
4. **Algorithm confusion**: Hardcoded `algorithms=["RS256"]` prevents downgrade attacks
