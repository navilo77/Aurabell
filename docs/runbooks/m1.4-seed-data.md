# M1.4 — Seed Data Runbook

## Overview

This runbook documents the step-by-step process to run migrations 001-011 and verify the seed data.

## Prerequisites

- Supabase CLI installed
- Docker running (for `supabase start`)
- PostgreSQL client (`psql`) for direct queries

## Step 1: Start Supabase Local

```bash
cd backend/supabase
supabase start
```

Expected output:
```
Started supabase local development setup.

API URL: http://localhost:54321
GraphQL URL: http://localhost:54321/graphql/v1
DB URL: postgresql://postgres:postgres@localhost:54322/postgres
Studio URL: http://localhost:54323
Inbucket URL: http://localhost:54324
```

## Step 2: Apply Migrations

```bash
supabase db reset
```

This runs all migrations in order (001-011).

## Step 3: Verify Role Count (7)

```bash
psql "postgresql://postgres:postgres@localhost:54322/postgres" -c "
SELECT name, description FROM public.roles ORDER BY name;
"
```

Expected output (7 rows):
```
      name       |      description
-----------------+------------------------
 admin           | Platform administrator
 customer        | Customer account
 inventory_manager | Inventory management
 order_manager   | Order management
 owner           | Platform owner
 store_manager   | Store management
 support_agent   | Customer support
```

```bash
# Quick count
psql "postgresql://postgres:postgres@localhost:54322/postgres" -c "
SELECT count(*) FROM public.roles;
"
# Should return 7
```

## Step 4: Verify Stores (2)

```bash
psql "postgresql://postgres:postgres@localhost:54322/postgres" -c "
SELECT name, slug, description FROM public.stores ORDER BY slug;
"
```

Expected output (2 rows):
```
      name      |    slug     |       description
----------------+-------------+-------------------------
 Aura Skin Care | aura-skin-care | Skincare and beauty store
 Best Gadget    | best-gadget    | Gadgets and electronics store
```

## Step 5: Verify Warehouse (1)

```bash
psql "postgresql://postgres:postgres@localhost:54322/postgres" -c "
SELECT w.name, w.location, s.name as store_name, s.slug as store_slug
FROM public.warehouses w
JOIN public.stores s ON s.id = w.store_id
WHERE w.name = 'Main Central Warehouse';
"
```

Expected output (1 row):
```
       name        |    location     |  store_name  |  store_slug
-------------------+-----------------+--------------+-------------
 Main Central Warehouse | Dhaka, Bangladesh | Best Gadget  | best-gadget
```

```bash
# Quick count
psql "postgresql://postgres:postgres@localhost:54322/postgres" -c "
SELECT count(*) FROM public.warehouses WHERE name = 'Main Central Warehouse';
"
# Should return 1
```

## Step 6: Verify RLS Enabled on Warehouses

```bash
psql "postgresql://postgres:postgres@localhost:54322/postgres" -c "
SELECT schemaname, tablename, rowsecurity
FROM pg_tables
WHERE tablename = 'warehouses';
"
```

Expected: `rowsecurity = t` (true)

```bash
# Verify policy exists
psql "postgresql://postgres:postgres@localhost:54322/postgres" -c "
SELECT policyname, cmd, roles, qual
FROM pg_policies
WHERE tablename = 'warehouses';
"
```

Expected: Policy "Store managers manage own warehouses" with FOR ALL cmd.

## Step 7: Run Automated Tests

```bash
cd backend
pytest tests/test_seed.py -v
```

Expected: All 7 tests pass (skipped if Supabase not running).

## Troubleshooting

| Issue | Resolution |
|-------|------------|
| Migration fails | Check `supabase db reset` output for specific error |
| Role count ≠ 7 | Verify migration 010 ran; check for duplicate key conflicts |
| Store count ≠ 2 | Verify migration 010 ran; check slug uniqueness |
| Warehouse count ≠ 1 | Verify migration 011 ran; check store_id FK to best-gadget |
| RLS not enabled | Verify migration 011 ALTER TABLE ran before INSERT |
