# M1.3 — Auth Endpoints API Specification

Base path: `/api/v1/auth`

## POST /auth/login

Authenticate user with email and password.

### Request

```json
{
  "email": "user@example.com",
  "password": "securepassword123"
}
```

| Field | Type | Required | Constraints |
|-------|------|----------|-------------|
| email | string | Yes | Valid email format |
| password | string | Yes | 8-128 characters |

### Response (200)

```json
{
  "access_token": "eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...",
  "refresh_token": "eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "bearer",
  "expires_in": 900
}
```

| Field | Type | Description |
|-------|------|-------------|
| access_token | string | JWT for API authentication (15 min) |
| refresh_token | string | Token to obtain new access token (7 days) |
| token_type | string | Always "bearer" |
| expires_in | integer | Access token lifetime in seconds |

### Errors

| Status | Code | Message |
|--------|------|---------|
| 401 | INVALID_TOKEN | Invalid credentials |
| 429 | RATE_LIMIT_EXCEEDED | Too many requests |

---

## POST /auth/register

Register a new user account.

### Request

```json
{
  "email": "newuser@example.com",
  "password": "securepassword123",
  "full_name": "John Doe",
  "phone": "+8801712345678"
}
```

| Field | Type | Required | Constraints |
|-------|------|----------|-------------|
| email | string | Yes | Valid email, unique |
| password | string | Yes | 8-128 characters |
| full_name | string | No | Max 150 chars |
| phone | string | No | Max 20 chars |

### Response (201)

Same as login response. If email confirmation required, tokens may be empty.

### Errors

| Status | Code | Message |
|--------|------|---------|
| 400 | REGISTRATION_FAILED | Email already exists or validation error |
| 429 | RATE_LIMIT_EXCEEDED | Too many requests |

---

## POST /auth/otp/request

Request OTP (magic link) via email for passwordless login.

### Request

```json
{
  "email": "user@example.com",
  "channel": "email"
}
```

| Field | Type | Required | Constraints |
|-------|------|----------|-------------|
| email | string | Yes | Valid email |
| channel | string | No | "email" or "sms" (default: "email") |

### Response (204)

No content. OTP sent to email.

### Errors

| Status | Code | Message |
|--------|------|---------|
| 400 | OTP_REQUEST_FAILED | Failed to send OTP |
| 429 | RATE_LIMIT_EXCEEDED | Too many requests |

---

## POST /auth/otp/verify

Verify OTP code and obtain tokens.

### Request

```json
{
  "email": "user@example.com",
  "code": "123456",
  "channel": "email"
}
```

| Field | Type | Required | Constraints |
|-------|------|----------|-------------|
| email | string | Yes | Valid email |
| code | string | Yes | Exactly 6 digits |
| channel | string | No | "email" or "sms" (default: "email") |

### Response (200)

Same as login response.

### Errors

| Status | Code | Message |
|--------|------|---------|
| 401 | INVALID_TOKEN | Invalid or expired OTP |
| 429 | RATE_LIMIT_EXCEEDED | Too many requests |

---

## POST /auth/refresh

Refresh access token using refresh token.

### Request

```json
{
  "refresh_token": "eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9..."
}
```

| Field | Type | Required | Constraints |
|-------|------|----------|-------------|
| refresh_token | string | Yes | Valid refresh token |

### Response (200)

Same as login response (new token pair).

### Errors

| Status | Code | Message |
|--------|------|---------|
| 401 | INVALID_TOKEN | Invalid or expired refresh token |

---

## POST /auth/logout

Sign out current user (revokes session server-side).

### Request

```
Authorization: Bearer <access_token>
```

### Response (204)

No content.

---

## Authentication for Protected Endpoints

Include access token in Authorization header:

```
Authorization: Bearer eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...
```

### Error Responses

| Status | Code | Message |
|--------|------|---------|
| 401 | AUTH_ERROR | Missing authorization header |
| 401 | INVALID_TOKEN | Malformed or invalid token |
| 401 | TOKEN_EXPIRED | Token expired |
| 401 | INVALID_ISSUER | Token issuer mismatch |
| 401 | INVALID_AUDIENCE | Token audience mismatch |
| 401 | USER_NOT_FOUND | No profile for token subject |
| 403 | PERMISSION_DENIED | Insufficient roles |
| 503 | JWKS_UNAVAILABLE | Signing keys unavailable |

## Example Usage

### Login Flow

```bash
# 1. Login
curl -X POST http://localhost:8000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email": "user@example.com", "password": "password123"}'

# Response: {"access_token": "...", "refresh_token": "...", "token_type": "bearer", "expires_in": 900}

# 2. Access protected endpoint
curl -X GET http://localhost:8000/api/v1/users/me \
  -H "Authorization: Bearer <access_token>"

# 3. Refresh token when expired
curl -X POST http://localhost:8000/api/v1/auth/refresh \
  -H "Content-Type: application/json" \
  -d '{"refresh_token": "<refresh_token>"}'

# 4. Logout
curl -X POST http://localhost:8000/api/v1/auth/logout \
  -H "Authorization: Bearer <access_token>"
```

### OTP Flow

```bash
# 1. Request OTP
curl -X POST http://localhost:8000/api/v1/auth/otp/request \
  -H "Content-Type: application/json" \
  -d '{"email": "user@example.com"}'

# 2. Check email for 6-digit code, then verify
curl -X POST http://localhost:8000/api/v1/auth/otp/verify \
  -H "Content-Type: application/json" \
  -d '{"email": "user@example.com", "code": "123456"}'
```
